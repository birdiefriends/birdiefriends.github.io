Writes REAL claims to the CTP Jotform form: a realistic 2-4 claim progression per hole (mostly improving, like groups leapfrogging each other through the day), PLUS three deliberate canary claims to prove the specific rules Close Round depends on — one hole gets a later claim that's intentionally FARTHER (proves the winner is timestamp-based, not distance-based), one claim is tagged with a wrong/mismatched round name (proves cross-round bleed can't happen), and one claim lands on a hole this round hasn't configured for CTP (proves it's silently ignored, not silently paid). We don't have real tee-time groupings in this model, so this can't replicate WHO would naturally submit when — it replicates the submission PATTERNS (staggered timing, superseding claims, stray/mismatched data) that actually exercise the matching logic, which is what determines correctness.

5. Tee policy

Same tee vs. by-HCP-tier is a one-time, event-wide choice. But different rounds can be at different venues, and different venues have different tee names and slopes — so the actual tee/slope values are captured separately, once per venue, below. A venue's block appears here once a stableford round above has that venue selected.

Add a stableford round above and pick its venue to see a tee policy block for it here.

6. Payout

Uses the same proportional formula as the BFSeries payout: podium 20% of pool (weighted split), CTP 15% spread across the round's CTP holes, remainder to skins. The Overall pot is podium-only (no CTP/skins). Wally Ball is a separate winner-take-all pool, split evenly if more than one player never loses the ball.

7. Save on the Worker

Rebuilds the config from whatever's currently in sections 1–6 and persists it into the Competitive Events tables (bfe_events → bfe_event_rounds → bfe_event_roster), keyed by the event name above — a real parent/child structure, not a single document (and, if checked in Tee policy, updates that venue's saved tee catalog too). You don't need to click "Generate event config" first — Save always regenerates from the current form right before it persists, so it can't send stale data. Generate on its own is still there if you just want to preview the Review tables below without saving. To load an event back, use Load in the Data & reset list at the top of the page — it picks from what's actually stored instead of retyping a name you might get wrong.

8. Close a round

Pulls that round's scorecards straight from Jotform, runs them through the quota engine above (including any Wally Ball bonus), computes skins and Closest-to-Pin, and saves the result — round pot payout included (podium, skins, and CTP). Only "Stableford quota" rounds are wired up right now; 2-man scramble scoring isn't built yet. CTP pays whoever's the most-recent qualifying claimant on each hole configured for this round's venue in section 5 — same rule the live leaderboard uses. Load or Generate the event above first.

10. Publish results page Phase 3

Builds the player-facing results page (round-by-round leaderboards, Skins/CTP, Wally Ball tracker, and Overall standings once every round rolling into it is closed) straight from what's already saved in bfe_round_results/bfe_round_skins/bfe_round_cttp — nothing here re-runs the scoring engine, it only reads back what Close Round already computed and pushes it to docs/<path> via the main Worker's existing /deploy route (same mechanism portal.html uses). Safe to re-run any time a round changes — it always overwrites the same page. Preview first; nothing is published until you click Generate & publish.
